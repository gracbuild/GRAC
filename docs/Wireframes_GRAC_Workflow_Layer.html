NEW · Task Centertasks§12.1.3

Screen purpose

Single home for every work item generated by the engine — Implementation, Rectification, Change, Waiver, Reverification, AssignmentPending, AuditDriven, RiskDriven. Owner-scoped by default; filters expand scope.

Navigation flow

Menu → Practice Management → Task Center. Deep links: /practice/tasks?type=Rectification&status=Open. Row → Task detail drawer. Detail → linked entity (Ticket / Finding / Instance).

Pagination: 25/page · sortable columns · sticky header · row click opens detail drawer.

Sections

  • Toolbar — Assignee scope · Type · Status · SLA · Priority · Criticality · Origin · Search.
  • Grid — 25/page, virtualized. Right-side drawer on click.
  • Detail drawer — Subject, description, linked entity link, state machine timeline, transition buttons (filtered by fn_can_mutate), comments, attachments.
  • Bulk actions bar — appears when ≥1 row selected: Assign, Escalate, Close (blocked when Implementation two-gate not green).

Fields (New Task form / drawer)

  • Task Type req — select from task_type_master.
  • Subject entity type + id req — resolves via search picker.
  • Linked release / control / practice / instance — auto-derived from subject; editable.
  • Assignee req — filtered to human employees only (excludes GRAC_SYSTEM).
  • Priority, Criticality — required.
  • SLA due at — auto per task_type_master.default_sla; overridable.
  • Reason code (dropdown), Reason text.

Buttons

Row 3-dot menu: Assign, Transition, Escalate, Close, Cancel, View linked entity, Copy link, Audit trail. Toolbar: + New Task, Saved filters, Export CSV.

Validation

  • Cannot save without required fields.
  • Close blocked when Implementation task and either gate not green (banner: "Config gate: OPEN. Operational gate: OPEN. Cannot close.").
  • Illegal state transition → 409 Conflict → toast with reason_code.
  • Assignee must satisfy SoD (§12.4.5) — Warn/Block on submit.

Popup dialogs

Transition Task

User interactions

  • Real-time badge in header when new Tasks land in inbox (SignalR later — for now, poll every 60s).
  • Sticky filters persisted per user in localStorage only (no server state).
  • Keyboard: N new task, / search, Esc close drawer.

State diagram

NEW · Applicability & NA Decisionsapplicability-decision§12.2.5

Guided workflow to mark a Control (or Practice adoption) as Applicable / Not Applicable with mandatory justification, approver, expiry, and reference URL. Reverification tasks open 30 days before expiry.

Navigation flow

Source Statements → row action "Decide applicability". Also embedded in organization-controls and organization-requirements partials.

Popup: NA decision modal

Mark Not Applicable — CTRL-104

On submit: an approval Task opens for the Release Owner; a Waiver record is created linked to this decision.

Fields, validation, interactions

  • Justification: min 20 chars, max 2000.
  • Approver: role scope must be RELEASE or higher.
  • Expiry: max 12 months default; org-configurable.
  • Reference URL: optional but validated as http/https.
  • Applicability change requires re-approval — auto opens a Task.
  • Reverification Task opens 30 days before expiry via na-expiry-sweeper.

3-dot menu

Design tokens & conventions

  • State pill palette — green good/passed, amber warning/late, red fail/breach, blue info/GRAC, grey neutral/custom.
  • Origin badges: GRAC and Custom.
  • Every grid row supports a 3-dot menu (⋮) for row actions, driven by /api/practice/permissions/probe. Disabled actions still render but with a lock icon and hover tooltip stating the reason (Deny / RequiresApproval).
  • Popup modals use brand-primary border, right-aligned action row (Cancel · Primary).
  • All new screens feature-flagged; header banner ("This feature is in preview.") appears when feature_flag.preview is on.
  • All datetimes rendered in the user's timezone; server always stores UTC.
